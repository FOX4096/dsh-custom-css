# 预览块

[← 返回 README](../README.md) · [文档索引](./index.md)

> **状态：设计已定，尚未实现。** 这一版是讨论之后重写的 —— 和最初那版比，主要变了三件事：
> 右上角**三个按钮**（全屏 / 对比 / 列表）、对比是「**左边多一块**」而不是两个陌生视口、
> 以及预览**不再用 iframe**（理由见下）。名字以 [`docs/naming.md` D 节](./naming.md) 为准。

---

## 它是什么

插在**代码区**与**规则面板**之间的整块 `.dshCc_preview`，**只在打开了某条规则时出现**
（和规则面板同进同退）。不给没在编辑的行增加高度。

预览的是**当前这条规则**：它把这条规则做了什么、在哪个元素上、和「没有它」有什么差别摆出来。

## 右上角三个按钮

按顺序，都在 `.dshCc_previewTools` 里：

| 顺序 | 按钮 | 标识 | 这一版 |
| --- | --- | --- | --- |
| 1 | **全屏** | `.dshCc_previewFull` | **只做按钮**（先占位，禁用并写明「全屏视图下一步做」） |
| 2 | **对比** | `.dshCc_previewCompare` | 切换对比模式：**左侧多出一块「生效前」**，右侧是「生效后」 |
| 3 | **列表** | `.dshCc_previewList` | 列表模式：把**命中到的元素逐个克隆**成一行，一行一个演示 |

左边还有 **规则文本**（`.dshCc_previewRule`）：当前规则的原文，只读，溢出省略。

## 三种模式

| 模式 | 屏幕上是什么 | 样本数 |
| --- | --- | --- |
| **单屏预览**（默认） | 一块「生效后」 | 1 |
| **对比模式** | **左「生效前」\| 右「生效后」**，各自带左上角小字与角上尺寸读数 | 2（同一个样本的两种样式） |
| **列表模式** | 一列「生效后」，每行对应一个命中元素 | ≤ 6（其余写「还有 N 个」） |

窄行（< 640px）下对比模式**上下堆叠**，不提示「先全屏」。

## 样本是怎么做出来的（这一版的核心）

不用 iframe，也不在真页面上切来切去。样本是**克隆 + 冻结样式**：

1. **取「生效前」的计算样式**：把用户表临时换成「**去掉当前规则的每一条同选择器规则**」，
   读目标元素的 `getComputedStyle`，再把表换回来。
   这一步与编辑器每次保存等价 —— 都是给同一个 `<style>` 换 `textContent`，所以没有额外代价。
2. **取「生效后」的计算样式**：表本来就完整，直接读。
3. **渲染**：把元素 `cloneNode(true)` 进 `.dshCc_sample`，把第 1/2 步读到的计算样式**写成内联**。
   内联优先级最高，因此样本只受这条规则影响，不会与页面里其他规则打架。

于是：**左块与右块的差异，只来自「有没有这条规则」** —— 这就是「这条规则干了什么」。

### 为什么不用 iframe

两条实测过的理由，第二条是决定性的：

- `--dsw-*` 令牌定义在**宿主 `body`** 上（见 [已知坑](./known-issues.md)），iframe 里没有；
  要用就得把几百个令牌序列化进去。
- **`backdrop-filter` 在 iframe 里模糊的是 iframe 自己的内容。** 一个透明的 iframe 里做毛玻璃，
  结果是「什么都模糊」= 一块干净的空盒子 —— 而这正是**预设**要展示的东西。用 iframe 做玻璃预览
  会得出与实际相反的结论。

### 保真度的诚实口径

| 真实 | 不真实 |
| --- | --- |
| 这条规则的**每一条声明**，叠加在元素**真实的计算样式**之上（包括继承来的字体、父级给的宽度） | **级联结果**：别的表里更高优先级的规则、`!important` 竞争、后续覆盖 |
| 元素在页面上的实际尺寸（取挂载那一刻的 `rect`，样本按它锁死） | 交互后的重新布局（悬停后元素长大、内容溢出……） |

所以预览块底部固定一行小字：**「样本冻结了元素当前的计算样式；级联与交互后的变化不在其中」**。
预览的价值是「改动与效果的距离」，不是「替代浏览器」。宁可在界面上写明局限，也不给一个看着像真的、
其实骗人的预览。

## 状态芯片（第二批）

`:hover` / `:focus` / 占位符 / `::before` / `::after`。这些**没法用冻结样式展示** ——
浏览器不让你读「悬停时」的计算样式。所以芯片走**另一套机制**：

把当前规则里的 `:hover` 改写成 `.dshCcStateHover`（`:focus` → `.dshCcStateFocus`，
占位符 → `:placeholder-shown` 之类），用一个临时表注入，再把那个类**临时**加到命中元素上；
关掉芯片或离开预览时撤掉。

代价写清楚：**这一段用的是真页面**，预览期间页面真的变了（只变这一条规则，且只在你勾选芯片时）。
所以芯片只在**单屏模式**出现，并且旁边挂一个显眼的「演示中」标记；「看原文」也复用同一条机制
（把整条规则从表里减掉再注入）。

## 命中 0 个时

用**合成样本**：拿真令牌拼一个方框，尺寸从规则里推（有 `width`/`height` 就用，没有用 `240×120`），
**明确标注**「这不是页面上的元素」。对比模式下两块都用**同一个**合成样本，所以左右差异仍然只来自
这条规则。

## 边界情况

| 情况 | 怎么办 |
| --- | --- |
| 当前规则命中 0 个 | 合成样本 + 标注 |
| 同一选择器有多条规则 | 「生效前」把**每一条**都减掉（口径见 [naming §F](./naming.md)） |
| 规则写在伪元素上（`a::before`） | 预览宿主元素本身，`::before` / `::after` 由状态芯片打开 |
| 规则在 `@media` / `@supports` 里 | 不显示（面板本来也编辑不到，见 [已知限制](./known-issues.md)） |
| 表很大 | 只对**这一条规则**做冻结样式，与表大小无关；取计算样式是常数次读操作 |
| 属性面板里的值正在被编辑 | 预览跟随**已写盘的值**，不跟半输入的值（与 [规则面板](./rule-panel.md) 的校验口径一致） |
| 命中的是插件自己的控件 | 照常预览（那样才看得出你自己写的规则有没有打到自己），但预览里不响应交互 |

## 布局

```
.dshCc_preview
├── .dshCc_previewHead
│   ├── .dshCc_previewRule       规则原文（省略号）
│   └── .dshCc_previewTools      全屏 | 对比 | 列表
├── .dshCc_previewStage
│   ├── .dshCc_previewBefore     对比模式才有：左上角「生效前」+ 尺寸读数
│   │   └── .dshCc_sample
│   └── .dshCc_previewAfter      「生效后」
│       └── .dshCc_sample
└── .dshCc_previewNote           冻结口径那一行小字
```

列表模式把 `.dshCc_previewAfter` 换成一列 `.dshCc_sampleRow`（每行：样本 + 元素类型 + 选择器片段）。

## 分阶段

| 阶段 | 内容 | 依赖 |
| --- | --- | --- |
| **1** | 预览块骨架 + 三个按钮（**全屏只占位**）+ 单屏预览 + 对比模式 | 无 |
| **2** | 列表模式（克隆每个命中元素）+ 状态芯片（真页面 + 临时表） | 阶段 1 的克隆代码 |
| **3** | [预设](./presets.md)（亚克力 / 毛玻璃 / 榆木 / 细描边卡片） | 与预览独立，可以并行 |
| **4** | 全屏视图（`Esc` 退出，左右强制并排，下半屏就是同一个规则面板） | 阶段 1、2 |

## 令牌

全部取自 DSH 自身（见 [naming §G](./naming.md)）：描边 `--dsw-alias-border-l2`、
底 `--dsw-alias-bg-module-platform`、视口底 `--dsw-alias-bg-layer-1`、
标签与读数 `--dsw-alias-label-caption`、聚焦环 `--dsw-alias-brand-primary`、
增删点缀色 `--dsw-alias-code-diff-added` / `--dsw-alias-code-diff-deleted`。
