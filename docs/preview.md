## 它是什么

插在**代码区**与**规则面板**之间的整块 `.dshCc_preview`，**只在打开了某条规则时出现**
（和规则面板同进同退）。不给没在编辑的行增加高度。

它回答的问题是 **「我刚才这一改，把它变成了什么样」** —— 左边是你打开这条规则时的样子，
右边是现在的样子。这也正是调值时的那一圈：改值 → 看效果。

## 工具栏：背景 + 三个按钮

按顺序，都在 `.dshCc_previewTools` 里：

| 顺序 | 控件 | 标识 | 这一版 |
| --- | --- | --- | --- |
| 0 | **背景**（下拉） | `.dshUi_choice`（`aria-label` = 画布背景） | 换画布背景，见上一节 |
| 1 | **全屏** | `.dshCc_hlToggle`（第一个） | 打开**全屏视图**（原生 `<dialog>`，`Esc` / × 退出） |
| 2 | **对比** | `.dshCc_hlToggle`（第二个，`aria-pressed`） | 切换对比模式：**左侧多出一块「当前」**，右侧是「修改后」 |
| 3 | **列表** | `.dshCc_hlToggle`（第三个，`aria-pressed`） | 切换**卡片导航**：一排卡片，一张卡对应一个命中元素 |

下拉不设死高度，靠内边距 + 行高跟着旁边那几个胶囊走 —— 36px 的 kit 默认值会把这行头部撑成两倍高。

左边还有 **规则文本**（`.dshCc_previewRule`）：当前规则的原文，只读，溢出省略。

## 画布：拖动、归位、背景预设

样本坐在一块**画布**里（`.dshCc_canvas`），行内与全屏各一块，共用同一个平移量。

| 交互 | 结果 |
| --- | --- |
| 按住画布拖动 | 样本跟着走（`transform: translate(…, …)`），行内与全屏同步 |
| 右下角「归位」/ 双击画布 | 回到原点 |
| 工具栏最左边的下拉 | 换画布背景：**页面**（默认）/ 棋盘 / 方格 / 斜纹 / 点阵 / 渐变 / 纯色 |

**画布是三层，从下往上**：

| 层 | 是什么 | 谁在用 |
| --- | --- | --- |
| ① 页面底 | `.dshCc_canvas` 的 `background-color` = `--dsw-alias-bg-layer-1` | **所有**档位都有 —— 画布永远不会是「透明的窗口」 |
| ② 图案墨 | `--dshCc-canvas-ink`（默认就是 `--dsw-alias-border-l2`，即 10% 黑）画的棋盘/方格/斜纹/点阵/渐变 | 判读用的那几档 |
| ③ 样本 | 克隆件 + 冻结的计算样式 | 一直是它 |

**为什么第一版看起来「卡片全透明了」**：那时画布是透的，图案直接压在面板上；而 DSH 的卡片底色是
**58% 白**（`--dsw-alias-bg-layer-1` 不是一个实色）—— 于是「58% 白 + 半透明图案 + 面板」三层一叠，
卡片自然透出底下的图案，看起来就像被改透明了。现在下面多了一层页面底，图案只以 42% 透出来；
而且默认那一档是 `page`（没有图案），预览和加画布之前**逐像素一致**。

要记住的口径：**半透明的东西在图案前就是会透**——这正是图案的用途。真的不透明（alpha = 1）的组件，
任何档位下都不可能透出图案。如果你的卡片看起来透了，它本来就不是实色。

三件事值得写下来：

1. **拖动不经过 React state**。一次 `pointermove` 走一次渲染，等于把整块面板连同克隆出来的样本
   一起重画（同一个判断见 `paintHighlightBoxes`）。平移量放在 ref 里，`transform` 直接写 DOM；
   归位按钮始终渲染，所以没有「拖没拖过」这个状态要维护。
2. **回到原点给空串**，不是 `translate(0px, 0px)` —— 后者仍然会建一个合成层、仍然会改变 `fixed`
   后代的包含块，于是「归位了但其实没归位」。
3. **除了 `page` 以外，画布负责底、谁都不许再铺一层**：判读用的背景下，样本框与合成样本都是透明底，
   否则图案只剩边框那一圈能看见，等于这个功能没做。真实元素的底色仍然来自冻结的计算样式 —— 所以
   半透明组件会真的透出棋盘格，而那正是选棋盘格的理由。

背景选择存在 `localStorage`（键 `dsh-custom-css:canvas`），**不进设置记录**：它是「看的时候的偏好」，
不参与注入，也不需要 Host 知道。认不出来的值一律退回 `page`。

## 三种模式

| 模式 | 屏幕上是什么 |
| --- | --- |
| **单屏预览**（默认） | 一块「修改后」 |
| **对比模式** | **左「当前」\| 右「修改后」**，各自带左上角小字与角上尺寸读数 |
| **卡片导航** | 预览上方（对比模式下是两块的上方）多一排卡片，见下 |

窄行（< 640px）下对比模式**上下堆叠**，不提示「先全屏」。

### 卡片导航（已实现）

**卡里放的是标签，不是缩略**（`button · 2/5`）：一次渲染里再克隆 6 份、每份三百多条内联声明，
代价比它带来的信息多 —— 而「长什么样」上面那块大样本已经给了。卡片复用 `.dshCc_hlToggle`
（选中态 `aria-pressed`），点哪张就把预览切到哪个命中元素。


一排横向卡片（`.dshCc_sampleCards`），**一张卡 = 一个命中元素**：

- 卡片里是那个元素的**克隆缩略**（同一套冻结样式，缩放显示），
- 卡片底部写元素类型与命中序号（`div · 2/5`），
- **点哪张卡，上面的预览就切到哪个元素**（单屏 / 对比都跟着切）。

为什么不做成「一堆样本竖着排」：一个选择器命中 30 个元素时，竖排会变成一面墙，而且每行都要
重新布局。卡片导航把「看哪一个」和「看什么」分开，同时保留「这个规则在别的元素上长什么样」的入口。

卡片最多 `12` 张，再多就横向滚动；**命中 0 个**时这一排只有一张「合成样本」卡。

## 样本是怎么做出来的（这一版的核心）

不用 iframe，也不在真页面上反复切换。样本是**克隆 + 冻结计算样式**：

1. **捕获基线**：从**这条规则被打开的那一刻**起，把当时的样式表文本记下来。换规则、关面板时清掉。
2. **读「当前」的计算样式**：把用户表临时换成基线文本 → 读目标元素的 `getComputedStyle` → 换回现在的文本。
   这一步与编辑器每次保存等价（都是给同一个 `<style>` 换 `textContent`），没有额外代价。
3. **读「修改后」的计算样式**：表本来就是现在的文本，直接读。
4. **渲染**：把元素 `cloneNode(true)` 进 `.dshCc_sample`，把第 2/3 步读到的计算样式**写成内联**。
   内联优先级最高，因此样本只受那两份文本影响，不与页面里其他规则打架。

于是两块样本是**同一个元素的两份真实计算样式**，差异只来自「你打开之后改了什么」。

### 为什么左边是「当前」而不是「去掉这条规则」

两种口径都合理，选这一个是因为预览块要服务的是**编辑循环**：

| 口径 | 左边显示 | 适合回答 |
| --- | --- | --- |
| **当前**（本版） | 你打开这条规则时的文本 | 「我刚改的这一下干了什么」——调值时问的就是这个 |
| 去掉这条规则 | 整表减掉它 | 「这条规则本身有什么用」——读别人的样式表时更像这个 |

第二种以后可以作为对比模式里的一个切换，但**第一版不做**：两个口径同时出现，会让人分不清左右
到底在比什么。

### 为什么不用 iframe

两条实测过的理由，第二条是决定性的：

- `--dsw-*` 令牌定义在**宿主 `body`** 上（见 [已知坑](./known-issues.md)），iframe 里没有；
  要用就得把几百个令牌序列化进去。
- **`backdrop-filter` 在 iframe 里模糊的是 iframe 自己的内容。** 一个透明 iframe 里做毛玻璃，
  结果是「什么都模糊」= 一块干净的空盒子 —— 而这正是**预设**要展示的东西。用 iframe 做玻璃预览
  会得出与实际相反的结论。

### 保真度的诚实口径

| 真实 | 不真实 |
| --- | --- |
| 两块都是**真级联**读出来的计算样式（各自在「当前文本」与「现在的文本」下） | **冻结**：尺寸按读那一刻的 `rect` 锁死，改完之后的重排（比如被内容撑高）不在其中 |
| 继承来的字体、父级给的宽度、`!important` 与更高优先级规则的胜负 —— 都在计算样式里 | **交互态**：`:hover` / `:focus` / 伪元素（见下方状态芯片） |
| 元素真实的背景、边框、阴影（含 `backdrop-filter`，因为样本就在真页面上） | 样本与页面重叠处的**视觉关系**：它被摆在预览框里，不在元素原来的位置上 |

所以预览块底部固定一行小字：**「样本冻结了元素的计算样式；改完之后的重排与交互态不在其中」**。

## 状态芯片（已实现，0.10.0）

`:hover` / `:focus` / 占位符 / `::before` / `::after`。前三个**没法用冻结样式展示** ——
浏览器不让你读「悬停时」的计算样式（只有 DevTools 的 CDP `forcePseudoState` 能，页面里没这个权限）。
所以芯片走**真页面强制 + 再读**的路子：

1. 把当前规则选择器里的 `:hover` 改写成 `.dshCcStateHover`（`:focus` → `.dshCcStateFocus`、
   `:placeholder-shown` → `.dshCcStatePlaceholder`），连同规则正文写进一张临时表
   （`#dsh-custom-css-preview-force`，追加到 head 末尾 —— 平局时它要赢）。
2. 把那个类加到**正在预览的那个元素**上。于是真页面进入该状态。
3. 样本重画时读到的就是**被强制之后**的计算样式 —— 预览里是真的悬停效果，不是猜的。

后两个（`::before` / `::after`）**不动页面**：伪元素不是节点，克隆带不走它；能做的是读它的计算样式、
造一个 `span.dshCc_samplePseudo` 把样式抄上去、把 `content` 当文本放进去，插在克隆的首 / 尾。
`content: url(...)` 这类不是文本的情况不合成（芯片 tooltip 里说明了）。

代价写清楚：**前三个用的是真页面**，预览期间页面真的变了（只变这一条规则，且只在你勾选芯片时）。
所以芯片只在**单屏模式**出现，旁边挂一个显眼的「演示中」标记；关掉芯片、换规则、关面板、切对比 / 全屏、
行卸载时都会 `clearPreviewForcing()`（删表 + 摘类）—— 少一处就会在页面上留下一个没主的类。

**一条实现上的必要修正**：`button:hover` 这样的规则在静止页面上**一个元素都匹配不到**，而预览正是要
看它的效果。所以找「宿主元素」时用的是**去掉状态伪类的选择器**（`button:hover` → `button`），再由
强制态把它送回悬停的样子 —— 否则 `:hover` 规则会掉进「命中 0 个」的合成样本路径。

## 命中 0 个时（已实现，0.10.0）

用**合成样本**：把这条规则自己的声明拼成一个方框（有 `width` / `height` 就用，没有给 `240×120`），
里面写着「合成样本（不是页面上的元素）」—— **明确标注**是硬要求：否则用户会去页面上找那个其实不存在
的东西。对比模式下两块都用**同一个**合成样本，所以左右差异仍然只来自你的改动。

## 边界情况

| 情况 | 怎么办 |
| --- | --- |
| 打开之后还没改过 | 两块一样 → 左块位置显示「还没改动：改一个值，左右就会分开」（**已实现**） |
| 当前规则命中 0 个 | 合成样本 + 标注（**已实现**） |
| 同一选择器有多条规则 | 两份文本各自完整应用，所以「当前」与「修改后」的差别天然覆盖所有同选择器规则 |
| 规则写在伪元素上（`a::before`） | 预览宿主元素本身；`::before` / `::after` 芯片把伪元素**合成**到样本里（`content` 是文本时） |
| 规则在 `@media` / `@supports` 里 | 不显示（面板本来也编辑不到，见 [已知限制](./known-issues.md)） |
| 表在别处被改过（外部编辑） | 基线不动、只更新右侧 —— 并在标签上写「当前（打开时）」 |
| 属性面板里的值正在被编辑 | 预览跟随**已写盘的值**，不跟半输入的值（与 [规则面板](./rule-panel.md) 的校验口径一致） |
| 规则命中的元素**本身**在排除名单里（默认 `:root, html, body`） | 不当样本：改用合成样本，并在面板里说明「这个元素在排除名单里（…）」。**只看元素自己，不看祖先** —— 否则 `:root` 会命中页面上所有元素，每条规则都退化成合成样本（真机上量到过） |
| 规则会命中预览自己（`[class*='_tableRow']` 这类宽选择器） | 两块样本容器带 `data-dshcc-owned`，`queryOwned` 会把它们和里面**所有克隆**从匹配里剔掉 —— 否则样本一画出来，计数就自己被自己喂大（真机上就是「会命中预览框内部内容」） |
| 规则命中的是表格行 / 单元格（`tr` / `td` / `th`） | 克隆件补上 `table > tbody` 包装：直接塞进 `div` 的 `<tr>` 没有布局，样本会是一片空白 |
| 命中的是插件自己的控件 | 照常预览（那样才看得出你自己写的规则有没有打到自己），但预览里不响应交互 |

├── .dshCc_stateChips            状态芯片（只在单屏模式）
├── .dshCc_canvas                画布（可拖、带背景预设）
│   ├── .dshCc_previewStage      ← 拖动改的就是它的 transform
│   │   ├── .dshCc_previewBox
│   │   │   ├── .dshCc_previewLabel（增删点缀色作底色的小标签）

└── .dshCc_previewNote           冻结口径那一行小字

├── .dshCc_full::backdrop        遮罩
├── .dshCc_fullHead              选择器 + ×
├── .dshCc_canvas                同一块画布（`flex:1 1 auto` 吃掉多出来的高度）
│   └── .dshCc_previewStage.dshCc_fullStage   左右并排（同样是那两块）
└── .dshCc_fullBody              同一份规则面板正文

高度：样本容器 **260px** 自己滚，整块面板 **340px**（原来是 160 / 260 —— 预览被声明区挤成一条缝）。

全屏视图（0.12.0 的设计）：卡片 `min(1280px,96vw) × min(94vh,960px)`、内边距 20、间距 16；舞台至少 260px 并吃掉多出来的高度，正文留在下半屏（最多 42%）自己滚；两块视口带 `0.5px --dsw-alias-border-l2` 描边（§G 的「视口描边」），样本短的时候在视口里**居中**（用 `margin:auto` 而不是 `justify-content:center` —— 后者在内容溢出时会让头几行滚不到）。

**顶栏是全屏里唯一的「我在哪」**：选择器（左）+ `N 个命中 · 第 i 个` + `‹ ›`（只在一个以上命中时出现，全屏里没有卡片导航，这对按钮是唯一的切换方式）+ `Esc 退出` + `×`。`‹ ›` 与 `×` 都是 28px 图标按钮（和面板右上角那个同一规格），不是 21px 的小胶囊 —— 一行里混两种控件高度，看起来像两条工具栏。

**窄窗口（≤900px）两张视口改成上下堆叠**：并排各 330px 时两边都看不出样子。这条媒体查询必须排在基础规则**之后** —— 媒体查询不加特异性，写在前面会被后面的 `flex-wrap:nowrap` 覆盖（实测：760px 下还是并排，量到两块视口 x=34/384、y 相同）。

**背景是毛玻璃**：`::backdrop{background:color-mix(in srgb,var(--dsw-alias-bg-overlay) 55%,transparent);backdrop-filter:blur(18px) saturate(1.15)}`。这里有个坑：`--dsw-alias-bg-overlay` 本身是**不透明**的 `#e9ecf2`，直接铺上去等于把页面盖死（模糊了什么都看不见），所以要先混成半透明。`prefers-reduced-transparency:reduce` 时退回不透明遮罩、去掉滤镜。进场 200ms ease-out（位移 12px），`prefers-reduced-motion` 时直接出现。

规格：块本身与其它块同一套（`radius-md` + `bg-module-platform` + `0.5px border-l2`，内边距 10、间距 8），
视口 `radius-sm` + `bg-layer-1`（内边距 8），说明文字用 `--dsw-font-xxs-12`（与历史版本页那条一致）。
两块的小标签用**增删点缀色作底色**（它们是 alpha 0.08 的底色，不是文字色 —— 详见 [设计一致性](./design-tokens.md)）。

## 分阶段
