# 命名表

> 这个插件里**每个界面元素只有一个名字**。代码、注释、测试、issue、README、
> 更新日志 —— 以及你和 AI 对话时 —— 都用这张表里的词，不再临时另起一个说法。
>
> 上一版的问题就出在没有这张表：同一个输入框被叫过「选择器字段」「规则名」
> 「面板标题框」，一句「那个框改一下」要来回问三轮才知道是哪一个。
>
> 状态一列的含义：**已实现** = 界面里已经有了；**规划中** = 设计已定、尚未写代码。

## 0. 一眼看清：这些名字是叠起来的

```
设置行                                    ← A
├── 行头                                  ← A
│   ├── 行标题「自定义 CSS」 / 行说明
│   └── 动作组                             ← A
│       ├── 拾取入口 [拾取元素]
│       ├── 查找入口 [查找]
│       ├── 文件下拉
│       └── 更多操作菜单
├── 文件栏                                 ← A
│   └── 文件身份区 / 大纲 / 状态点 / 启用开关
└── 编辑容器                               ← A
    ├── 编辑表头（文件名 + CSS 徽章 + 启用开关）
    ├── 编辑正文                           ← A
    │   ├── 代码区                        ← B
    │   │   ├── 行号列 / 代码文本框 / 彩色层 / 补全列表
    │   │   └── 查找栏（查找框 / 替换框 / 命中计数 / 大小写钮 / 替换钮）
    │   ├── 预览块                        ← D   ← 插在这一段
    │   │   ├── 预览头部
    │   │   │   ├── 规则文本
    │   │   │   └── 预览工具组 → [对比按钮] [全屏按钮]
    │   │   ├── 状态芯片组 → 状态芯片 ×N
    │   │   └── 预览视口
    │   │       ├── 单屏预览  ← 默认
    │   │       └── 对比预览  ← 对比模式：原始视口 | 修改后视口
    │   │           （各带视口标签与尺寸读数）
    │   └── 规则面板                       ← C
    │       ├── 选择器字段（内部有面板关闭钮 ×）
    │       ├── 属性网格 → 声明行 → 分量格
    │       ├── 添加属性菜单
    │       └── 插入模板区 → 模板 chip ×N
    └── 状态行

全屏视图                                  ← E（盖在整行之上）
├── 全屏遮罩
└── 全屏卡片
    ├── 全屏顶栏 → 全屏选择器框 + 全屏退出钮
    ├── 全屏预览区 → 原始视口 | 修改后视口
    └── 全屏规则面板（就是上面那个规则面板）
```

> **注意「预览块」的位置**：它在**编辑正文**里、**代码区**与**规则面板**之间。
> 别叫它「编辑器下面那块」——`规则面板`也在编辑器下面，这正是以前会混的地方。

## F. 「这两边到底差什么」的口径

对比模式不是在比「两张样式表」，是在比**你打开这条规则之后改了什么**：

| 面板 | 里面是什么 |
| --- | --- |
| **当前** | **打开这条规则那一刻**的样式表文本，应用在这个元素上的计算样式 |
| **修改后** | **现在的**样式表文本，应用在这个元素上的计算样式 |

两块都是**同一个元素的克隆**，样式**冻结成内联**（见 [预览块](./preview.md)）—— 所以左右只差
你打开之后的改动。**同一选择器有多条规则时不用特殊处理**：两份文本各自完整应用，差别天然覆盖它们。

另一种口径（左边 = 整表**去掉**这条规则）回答的是另一个问题（「这条规则本身有什么用」），
留作以后的可选切换，第一版不做。

## H. 怎么用这套名字

1. **提需求**：说名字就够 —— 「预览头部右上角加第三个按钮」比「上面那块右边再加个东西」少三轮确认。
2. **写代码**：类名用标识那一列的前缀（`.dshCc_preview…`），组件名用同一套词。
3. **记日志**：`info` 级别的日志要能说出是**哪个名字**做了**什么**（如「预览视口：重绘，命中 3 个样本」），你点了一个按钮没反应时，日志能告诉你是哪个。
4. **改名字**：先改这张表，再改代码 —— 表是口径，不是代码的摘抄。

### 这张表不覆盖已发布的名字

`dsh.client` / `dsh.bundle` / `compat.json` / `cordis.patch.yml` 里的**类名与文件**是已经
发到 npm 的东西，改它们会让别的插件、别人写的样式表、以及 `docs/` 下那四张架构图一起
对不上。所以：

- 这张表是**给人说话用**的 —— 它规定的是「这块东西叫什么」，不是「这个 class 要改成什么」。
- 表里「标识」一列是**现状的对照**；新加的东西（D/E 两节）才由这张表指定标识。
- 架构图与 README 里旧的说法，按位置能对上的以**本表**为准。
